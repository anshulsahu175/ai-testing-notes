01

What is Artificial Intelligence (AI)?

What AI is, why it is used, and where it shows up in real-world software.

Technical Definition

Artificial Intelligence (AI) is the field of computer science concerned with building computational systems that perform tasks normally requiring human intelligence, such as perception, reasoning, learning, natural language understanding and decision-making, typically by learning statistical patterns from data and applying them to new inputs.

Terms Used
Computational system
Software (and hardware) that takes data in, processes it, and gives a result out.
Perception
Making sense of raw sensory data, such as recognising objects in an image or words in speech.
Reasoning
Drawing conclusions or working out answers from the information available.
Learning
Improving at a task through experience (data) instead of being told every step.
Natural language understanding
Understanding the meaning of human language such as Hindi or English text.
Decision-making
Choosing the best option or action among several possibilities.
Statistical pattern
A regularity that holds most of the time across many examples, e.g. "emails with many links are often spam".
Input
The data given to the system to act on: a photo, a sentence, a transaction.
Deep Understanding
  • AI is a goal (intelligent behaviour), not one specific technique or algorithm.
  • Modern AI mostly learns from data rather than being explicitly programmed for every case.
  • Today's AI is Narrow AI: very good at one specific task, not general human-level intelligence.
  • AI output is a best estimate based on patterns, so it can be wrong even when it sounds confident.
  • In a real product, the AI part is usually one component inside a larger, normal software system.
Explanation
In simple words

AI means teaching a machine to do jobs that normally need human understanding: recognising things, understanding language, and making decisions.

A normal program is told every step: "do this, then do that". An AI system is not given every step. We show it a large number of examples and it works out the pattern by itself. On a new input, it answers using that pattern.

Why is AI used?

  • Where rules are hard to write: writing if-else rules for "what a cat looks like" is nearly impossible, but it can be learned from thousands of photos.
  • Handling huge data: finding fraud in millions of transactions is beyond human capacity.
  • Personalisation: a different recommendation for each user.
  • Automation: doing repetitive judgement tasks quickly, such as sorting support tickets into categories.

Tester Focus

When you test an app, first identify which features are AI-based. Those features need a different testing strategy from the rest, because their output is not always 100% fixed (Topic 3 covers this in detail).

Does a calculator app use AI?

No. A calculator follows fixed rules (arithmetic) and learns nothing from data. 2 + 2 will always be 4. It is traditional software.

Summary: AI = a machine that learns patterns from examples to do tasks that need human-like understanding.
02

AI vs Machine Learning vs Deep Learning

The relationship between AI, ML and DL, and their key differences.

Technical Definition

AI is the broad discipline of creating intelligent machines. Machine Learning (ML) is a subset of AI in which algorithms learn a mapping from data without being explicitly programmed. Deep Learning (DL) is a subset of ML that uses multi-layered artificial neural networks to learn hierarchical representations directly from raw data.

Deep Learning ⊂ Machine Learning ⊂ Artificial Intelligence
Terms Used
Subset
A smaller group that lies completely inside a bigger group.
Algorithm
A fixed, step-by-step procedure for solving a problem, here a procedure for learning from data.
Mapping
The relationship that connects an input to its output, e.g. email → spam / not spam.
Explicitly programmed
A developer writing every rule by hand in code.
Artificial neural network
A model loosely inspired by the brain, made of connected units (neurons) that pass numbers to each other.
Multi-layered
Neurons arranged in many layers, one after another; "deep" refers to this depth.
Hierarchical representation
Learning simple features first (edges), then combining them into complex ones (eyes, then faces).
Raw data
Unprocessed data such as image pixels, audio waves, or plain text.
Deep Understanding
  • The relationship is nested: every DL is ML and every ML is AI, but not the other way round.
  • ML's key difference from classic AI: the rules are learned, not hand-written.
  • DL's key difference from classic ML: features are learned automatically, not hand-engineered.
  • DL needs far more data and compute (GPUs) but performs best on images, audio and text.
  • More depth brings more power but less explainability.
Explanation

Each one on its own

  • AI (Artificial Intelligence): the biggest goal, giving a machine intelligent behaviour. It also includes older rule-based "expert systems" that do not learn.
  • ML (Machine Learning): one way of building AI, in which the machine learns from data by itself; we do not write the rules. For example, estimating a new house's price from past house prices.
  • DL (Deep Learning): a particular kind of ML that uses Artificial Neural Networks with many layers (hence "deep"). It works best on complex data such as images, speech and language. ChatGPT, Claude and face recognition all run on DL.

Tester Focus

DL models are often called a "black box": it is hard to say why the model gave a particular answer. So in testing we focus less on "why" and more on output behaviour across many inputs: accuracy, consistency and edge cases.

Does every AI system use Machine Learning?

No. A rule-based expert system is also called AI, but it does not learn from data. ML is just one (the most popular) way of building AI.

Summary: AI = the goal, ML = learning from data, DL = powerful ML built on neural networks.
03

Traditional Software vs AI-Based Software

How deterministic traditional software differs from probabilistic AI software. The most important topic for a tester.

Technical Definition

Traditional software is deterministic: its behaviour is fully defined by explicitly coded logic, so a given input in a given state always produces the same output. AI-based software is probabilistic: its behaviour is defined by a model learned from data, and it outputs the most likely result together with a probability / confidence score, which may vary for the same input.

Terms Used
Deterministic
The result is fixed in advance: same input, same output, every time.
Explicitly coded logic
Conditions and calculations a developer wrote line by line.
State
The system's current condition (stored data, settings) that can affect the output.
Probabilistic
The result is based on likelihood, not certainty; the model picks what is most probable.
Model
The function learned from data that produces outputs (Topic 9).
Probability / Confidence score
A number between 0 and 1 showing how likely the model thinks its answer is, e.g. 0.87.
Variable output (non-determinism)
The output can change across runs, due to random sampling, model updates or ambiguous input.
Deep Understanding
  • Deterministic = predictable and repeatable; probabilistic = likely, not guaranteed.
  • In AI software, "correct" is measured statistically (accuracy over many cases), not per single case.
  • Variation comes from random generation settings (sampling / temperature), model version changes, or ambiguous input.
  • AI software can be "working as designed" and still give a wrong answer for some inputs.
  • Most real products are hybrid: deterministic code wrapped around a probabilistic model.
Explanation
In simple words

Traditional software always gives the same answer for the same input. AI software gives its "best guess" with a confidence level, and that guess can sometimes differ even for the same input.

  • Deterministic: calculateGST(1000) will return 180 today, tomorrow, and on the millionth run.
  • Probabilistic: the model says "I think there is an 87% chance this email is spam." A generative AI (a chatbot) may word its answer a little differently each time you ask the same question.

      Tester Focus · The key takeaway
      • A traditional test case reads: "Input X → Expected Output Y, exactly."
      • AI output can change for the same input, so don't pass or fail it after one run. Run the same input several times and check consistency.
      • Write expected results as a range or criteria: "Label = Spam, confidence ≥ 0.80" or "the answer correctly states the refund policy."
      • Measure accuracy on many inputs (a test dataset), not one: "940 correct out of 1000 = 94%."
      • When the model is updated (retrained), rerun old passing cases; behaviour can change even if no code changed.
      You asked an AI chatbot the same question twice and the wording differed. Is that a bug?

      Not necessarily. Generative AI is probabilistic, so different wording is normal. It is a bug when the meaning is wrong, facts change, or the answer fails the requirement's criteria.

      Summary: Traditional = deterministic (fixed output); AI = probabilistic (likely output + confidence).
      04

      Rule-Based Systems vs AI Systems

      Systems that follow predefined rules compared with systems that learn patterns from data.

      Technical Definition

      A rule-based system makes decisions from a fixed set of human-authored IF–THEN rules applied by an inference engine to a knowledge base. An AI (learning) system derives its decision logic automatically by learning patterns from training data, and can generalise to inputs that no rule explicitly covers.

      Terms Used
      Human-authored rules
      Rules written by a person, usually a domain expert.
      IF–THEN rule
      A condition and its action: IF this is true, THEN do that.
      Inference engine
      The part of a rule-based system that checks which rules match and applies them.
      Knowledge base
      The stored collection of facts and rules the system uses.
      Pattern
      A repeated relationship in data that the model picks up.
      Training data
      The examples a model learns from.
      Generalise
      Handle new, unseen inputs correctly using what was learned.
      Deep Understanding
      • A rule-based system is only as smart as the rules someone wrote; unseen cases break it.
      • Learning systems trade explainability for flexibility.
      • Rule-based systems are transparent and auditable, best when logic is clear, stable and must be exact.
      • Rule explosion: as cases grow, rules multiply and start to conflict with each other.
      • Many production systems combine both: a model score plus business rules as guardrails.
      Explanation
      In simple words

      A rule-based system runs on if-then rules that a person wrote. An AI system learns the pattern from data and builds its "rules" internally.

      Example · A spam filter built both ways

      Rule-based:

      IF subject contains "FREE" OR "lottery" THEN mark as Spam

      The problem: a spammer writes "FR33" and the rule fails. Every new trick needs a new rule.

      AI-based: show the model 100,000 emails already marked "Spam" or "Not Spam". It learns which words, links and sender patterns signal spam, and often catches emails using new tricks too.

      PointRule-Based SystemAI System
      KnowledgeWritten by an expertLearned from data
      New situationFails if no rule existsCan estimate from patterns
      Explaining a decisionEasy: "Rule #12 fired"Hard (black box)
      OutputDeterministicProbabilistic
      MaintenanceRules pile up and tangleRetrain with new data
      Best forClear, few, stable rules (tax, eligibility)Complex patterns (images, language, fraud)
      Tester Focus

      In a rule-based system you can write a test case per rule (boundary values, decision tables). In an AI system the rules are invisible, so testing is data-driven: check behaviour with varied, tricky and unseen inputs. Many real products contain both (an AI score plus a business rule), so test each part separately.

      "If age ≥ 18, the person can vote": AI or a rule?

      A rule. The logic is clear, fixed, and must be 100% correct. Using AI here would be overkill and risky.

      Summary: Rules = written by people, limited but explainable. AI = learned from data, flexible but probabilistic.

      05

      Dataset, Features, and Labels

      The role of datasets, input features and expected labels in machine learning.

      Technical Definition

      A dataset is a structured collection of examples (data points) used to train and evaluate a model. Each example is described by features, the measurable input variables (X), and, in supervised learning, a label, the target output (y) the model should learn to predict.

      Dataset = { (X₁, y₁), (X₂, y₂), … , (Xₙ, yₙ) }
      Terms Used
      Structured collection
      Data organised in a fixed format, usually rows and columns like a table.
      Example / data point / sample
      One row of the dataset, i.e. one record such as one house or one email.
      Train
      Let the model learn its parameters from data.
      Evaluate
      Measure how well the trained model performs on data it has not seen.
      Feature
      One measurable property of an example, such as area or number of bedrooms.
      Input variables (X)
      All the features together that go into the model.
      Label / Target (y)
      The correct answer for an example, such as the actual price or "Spam".
      Deep Understanding
      • A model can never be better than its data: garbage in, garbage out.
      • Features are all the model "sees"; if a useful signal is missing from the features, the model cannot use it.
      • Labels define what "correct" means for the model; wrong labels teach wrong behaviour.
      • Training, validation and test data must stay separate to measure true performance.
      • Data must represent the real-world population the model will serve.
      Explanation
      In simple words

      A dataset is a table of examples. The columns describing each example are the features, and the column with the right answer is the label.

      Example · House price dataset
      Area (sq ft)BedroomsCityAge (yrs)Price (₹ lakh) — Label
      12002Indore548
      18003Pune2110
      9002Bhopal1230
      • Each row = one example (data point / sample).
      • The first four columns = features (inputs, written X).
      • The last column = label (output / target, written y).

      The three parts of a dataset (data split)

      • Training set (~70–80%): the model learns from this.
      • Validation set (~10–15%): used to tune settings while training.
      • Test set (~10–15%): data the model has never seen; the final exam that measures real performance.

      Signs of a good dataset

      • Quality: labels are correct.
      • Quantity: enough examples.
      • Diversity / representative: covers every kind of case: every city, age group, language.
      • Balanced: no class has far more examples than another.
      Tester Focus
      • Test data must be separate from training data. If the model has already "seen" the test examples (data leakage), accuracy will look falsely high.
      • Include edge cases, missing values, wrong formats, other languages and spelling variants in test data.
      • Check label quality too. Sometimes the model is right and the test data's label is wrong.
      For email spam detection, what are the features and the label?

      Features: email text, sender, number of links, whether there is an attachment, number of CAPITAL words. Label: Spam / Not Spam.

      Summary: Dataset = the table, Features = input columns (X), Label = the correct answer (y).
      06

      Supervised Learning

      How models learn from labeled data, and where supervised learning is used.

      Technical Definition

      Supervised learning is a machine-learning paradigm in which a model learns a function f: X → y from a labeled training dataset of input–output pairs, by iteratively minimising a loss function that measures the difference between its predictions and the true labels (ground truth).

      Terms Used
      Paradigm
      A general approach or style of doing something; here, a style of learning.
      Function f: X → y
      A rule that converts input X into output y.
      Labeled training dataset
      Training examples where every input already has its correct answer attached.
      Input–output pair
      One example plus its answer, e.g. (email, "Spam").
      Iteratively
      Repeating the same step many times, improving a little each time.
      Minimise
      Make as small as possible.
      Loss function
      A formula that gives a number for how wrong the predictions are; lower is better.
      Ground truth
      The actual, correct answer, which the prediction is compared against.
      Deep Understanding
      • "Supervised" means the correct answer is provided during training.
      • Learning = reducing the error between prediction and label, step by step.
      • It has two families: classification (categories) and regression (numbers).
      • The goal is generalisation to unseen data, not memorising training data.
      • The cost of getting labels is the main practical bottleneck.
      Explanation
      In simple words

      We give the model inputs together with their correct answers. The model learns the link between input and answer so it can answer correctly for new inputs.

      Analogy

      A teacher shows a child flashcards: "this is 🍎, this is 🍌." After many cards, the child can name a new fruit alone. The teacher is the labels, which is why it is called "supervised" (learning under supervision).

      How learning happens

      1. Show the model an example (its features).
      2. The model makes a guess (prediction).
      3. Compare the guess with the correct label. The difference is the error / loss.
      4. The model nudges its internal numbers (weights) so the error goes down.
      5. Repeat over thousands of examples. The error gradually shrinks.

      Two main types

      • Classification: the label is a category (Spam / Not Spam).
      • Regression: the label is a number (house price). Details in Topic 15.

      Where it is used

      • Spam detection, fraud detection
      • Whether a loan will be approved
      • Detecting disease in X-rays
      • Sales and price prediction
      • Customer review sentiment
      Tester Focus

      Supervised models are the most straightforward to test because the correct answer (label) exists. Compare predictions to expected labels and compute metrics like Accuracy, Precision and Recall. A model is only as good as its labels, so label quality is a risk area too.

      What is the biggest limitation of supervised learning?

      Creating labeled data is expensive and slow. People have to label millions of images by hand, and if the labels contain mistakes, the model learns those same mistakes.

      Summary: Supervised = teaching with inputs plus correct answers. Output: a category or a number.
      07

      Unsupervised Learning

      How models find patterns, groups or relationships without predefined labels.

      Technical Definition

      Unsupervised learning is a machine-learning paradigm in which a model discovers hidden structure, such as clusters, associations, low-dimensional representations or anomalies, in unlabeled data, typically by measuring similarity between examples, without any target output being provided.

      Terms Used
      Hidden structure
      Organisation that exists in the data but is not written down anywhere.
      Cluster
      A group of examples that are more similar to each other than to the rest.
      Association
      A relationship where items tend to occur together, like bread and butter.
      Low-dimensional representation
      Describing data with fewer features while keeping its important information.
      Anomaly
      An example that is very different from the normal pattern; an outlier.
      Unlabeled data
      Data with inputs only and no correct answers attached.
      Similarity / distance
      A numerical measure of how alike two examples are.
      Deep Understanding
      • No labels means there is no "right answer" to compare against.
      • The model groups items by the similarity of their features.
      • The model finds groups; humans give them meaning and names.
      • It is often used for exploration before building a supervised model.
      • Results depend heavily on the chosen features and settings, such as the number of clusters.
      Explanation
      In simple words

      The data has no labels. The model looks for structure on its own: which items are alike, which are different, and which tend to appear together.

      Analogy

      You get a big box of unlabeled buttons. You sort them into groups by colour, size and shape. Nobody told you what the groups should be. That is unsupervised learning.

      Main techniques

      • Clustering: forming groups of similar items. Example: splitting e-commerce customers into "budget buyers", "festival shoppers" and "premium buyers" (customer segmentation).
      • Association: what goes together. Example: "people who bought bread often bought butter" (market basket analysis).
      • Anomaly detection: catching what is very different from the rest. Example: a sudden large foreign transaction at 3 a.m.
      • Dimensionality reduction: reducing many features to fewer while keeping key information.
      PointSupervisedUnsupervised
      LabelsYesNo
      GoalPredict the right answerFind hidden patterns / groups
      OutputKnown category or numberGroups / clusters that a human names later
      ExampleSpam filterCustomer segmentation
      Tester Focus

      There is no predefined "correct answer", so pass/fail is hard to define. Check whether the groups make business sense, and whether running again on the same data produces roughly the same groups (stability). For anomaly detection, insert known fraud cases and check they get caught.

      Netflix split users into 5 groups based on viewing habits without defining the groups first. Which type of learning is this?

      Unsupervised learning (clustering). The groups weren't defined in advance; the model created them from the data.

      Summary: Unsupervised = finding groups and patterns in data without labels.
      08

      Reinforcement Learning

      How an AI system learns through rewards, penalties and interaction with an environment.

      Technical Definition

      Reinforcement learning (RL) is a machine-learning paradigm in which an agent learns a policy, a mapping from states to actions, by interacting with an environment through trial and error, receiving scalar rewards or penalties, with the objective of maximising cumulative reward over time.

      Terms Used
      Agent
      The learner and decision-maker, such as a game-playing AI or a robot.
      Policy
      The learned strategy: "in this situation, take this action".
      State
      The current situation of the environment as the agent sees it.
      Action
      A move or choice the agent makes.
      Environment
      The world the agent operates in: a game, a road, a simulation.
      Trial and error
      Trying actions, seeing results, and repeating what worked.
      Scalar reward
      A single number telling the agent how good its action was (positive = reward, negative = penalty).
      Cumulative reward
      The total reward added up over many steps, not just the next step.
      Deep Understanding
      • There are no labeled answers, only feedback on how good an action was.
      • Decisions are sequential: an action now affects rewards later.
      • The agent balances exploration (trying new things) against exploitation (using what works).
      • The agent optimises exactly the reward it is given, which can lead to reward hacking.
      • RLHF uses human preferences as the reward to make chatbots more helpful and safe.
      Explanation
      In simple words

      The agent tries actions. Good actions earn a reward and bad ones a penalty. Over many attempts it learns the way of acting that earns the most reward.

      Example · Teaching a dog a trick

      The dog sits → gets a biscuit (reward). It jumps → gets nothing. Within a few days it learns that sitting on "sit" pays off. Nobody gave it labels; it learned from outcomes.

      Real uses: game-playing AI (AlphaGo), self-driving cars, robots learning to walk, ad bidding, and improving chatbots like ChatGPT and Claude with human feedback (RLHF: Reinforcement Learning from Human Feedback).

      TypeLearns fromIn one line
      SupervisedLabeled dataA teacher gives the right answer
      UnsupervisedUnlabeled dataFinds groups on its own
      ReinforcementRewards / penaltiesLearns by doing and making mistakes
      Tester Focus

      An RL agent sometimes learns a wrong shortcut to collect reward (reward hacking), such as circling one spot in a game to rack up points. Test not only the score but also whether the behaviour is safe and sensible, especially in unusual situations.

      In RL, what plays the role of the "label"?

      The reward signal. The agent is never told the correct answer, only how good its action was.

      Summary: RL = agent + environment + reward; learning the best policy through trial and error.

      09

      AI Model

      What an AI model is and how it turns input data into predictions or outputs.

      Technical Definition

      An AI model is a parameterised mathematical function, produced by running a learning algorithm on training data, that maps input features to an output such as a class, a numeric value, or generated content. Its form is fixed by its architecture, and its behaviour by its learned parameters (θ).

      ŷ = f(X; θ)
      Terms Used
      Parameterised
      Its behaviour depends on adjustable internal numbers (parameters).
      Mathematical function
      A calculation that takes numbers in and gives numbers out.
      Learning algorithm
      The procedure that sets the parameters from data, e.g. gradient descent.
      Map
      Convert each input into a corresponding output.
      Output ŷ ("y-hat")
      The model's predicted value; the hat means "estimated", not the true y.
      Architecture
      The structure of the model: how its calculations are arranged (linear, tree, neural network).
      θ (theta)
      Standard symbol for all the model's learned parameters together.
      Deep Understanding
      • Model = architecture + learned parameters.
      • The algorithm is the recipe; the model is the dish it produces.
      • A model only knows the patterns that were present in its training data.
      • The same architecture trained on different data gives a different model.
      • Models are versioned artifacts; behaviour is tied to a specific version.
      Explanation
      In simple words

      A model is the "brain" that training produces. It takes input and gives output, using what it learned from data.

      Input (features) → [ Model: f(X) ] → Output (prediction)

      Analogy

      A model is like an experienced chef. Years of cooking (training) have built up an instinct. Give them a new vegetable (input) and they decide how much salt it needs (output). All that experience is the "model".

      What's inside a model

      • Architecture: the model's skeleton, i.e. the structure its calculation follows (linear model, decision tree, neural network). A person chooses this.
      • Parameters (weights + bias): the numbers learned during training. This is the actual "knowledge".

      Saving a model means saving the architecture plus the learned parameters. Large models like ChatGPT have billions of parameters.

      Popular model types

      • Linear regression: predicts a number with a straight line.
      • Logistic regression: gives a yes/no probability.
      • Decision tree: a tree of questions (like if-else, but learned from data).
      • Neural network: a multi-layer model, the basis of deep learning.
      • LLM (Large Language Model): a very large neural network for language, such as GPT or Claude.
      Tester Focus

      Models have versions too (e.g. fraud-model v2.3). Always record the model version in bug reports, because a new version can give a different output for the same input. Treating the model as a black box and testing it through inputs and outputs is the most common approach.

      What is the difference between a model and an algorithm?

      An algorithm is the learning method (the recipe), such as "linear regression". A model is what you get after running that algorithm on data: the final function, including its learned numbers.

      Summary: Model = a function learned from data: input → output. Architecture + parameters.
      10

      Parameters

      What model parameters are, and how learned numerical values shape model behaviour.

      Technical Definition

      Parameters are the internal numerical variables of a model, such as weights and biases, whose values are learned from training data by an optimisation algorithm (e.g. gradient descent), and which together determine how the model transforms inputs into outputs. They differ from hyperparameters, which are set by humans before training.

      Terms Used
      Internal numerical variable
      A number stored inside the model that can change value.
      Weight
      A parameter that sets how strongly an input affects the output (Topic 11).
      Bias
      A parameter added to the result to shift the output up or down (Topic 12).
      Optimisation algorithm
      A method that searches for parameter values that make the loss as small as possible.
      Gradient descent
      The most common optimiser: it moves each parameter a little in the direction that reduces error.
      Hyperparameter
      A setting chosen by a person before training, such as learning rate or number of layers.
      Deep Understanding
      • Parameters are the model's learned knowledge, stored as numbers.
      • Changing parameters changes behaviour, even when the code stays the same.
      • Parameter count shows a model's capacity, not a guarantee of quality.
      • Parameters are learned; hyperparameters are chosen by people.
      • Too many parameters for too little data leads to overfitting.
      Explanation
      In simple words

      Parameters are the numbers inside a model that it learns and adjusts by itself during training. Weights and bias are both parameters.

      Example · The simplest model
      Price = w × Area + b

      w and b are the two parameters. They start out random. Suppose training ends with w = 0.04, b = 2. Then a 1200 sq ft house = 0.04 × 1200 + 2 = ₹50 lakh.

      Change w and every prediction changes. Parameters decide the model's behaviour.

      Parameters vs hyperparameters

      PointParametersHyperparameters
      Who sets themThe model learns themA person (ML engineer) sets them before training
      ExamplesWeights, biasLearning rate, number of layers, epochs
      AnalogyWhat the student learnedHow long and how the teacher taught

      A sense of scale

      • Simple house price model: 2–10 parameters
      • Image recognition model: millions to tens of millions
      • Large LLMs: billions, e.g. a "7B model" has 7 billion parameters
      Tester Focus

      Testers don't usually look at parameters directly, but it matters to know that retraining = changing parameters. So model behaviour can change while the code stays identical, which makes regression testing essential.

      Is "learning rate" a parameter or a hyperparameter?

      A hyperparameter. A person sets it before training; the model doesn't learn it from data.

      Summary: Parameters = the model's learned numbers (weights + bias). They hold its knowledge.

      Weights

      How weights represent the relative influence of each input on the output.

      Technical Definition

      A weight is a learnable parameter that multiplies an input feature (or a neuron's input), scaling its contribution to the model's output. Its magnitude reflects the strength of influence and its sign indicates whether the influence is positive or negative. Inputs and weights are combined as a weighted sum.

      z = w₁x₁ + w₂x₂ + … + wₙxₙ + b
      Terms Used
      Learnable parameter
      A number the model sets for itself during training.
      Multiply / scale
      Make an input's effect bigger or smaller by multiplying it.
      Neuron
      A small unit in a neural network that computes a weighted sum and passes it on.
      Contribution
      How much one input adds to the final output.
      Magnitude
      The size of the number, ignoring its sign (|−0.8| = 0.8).
      Sign
      Positive (+) or negative (−); tells whether the input pushes the output up or down.
      Weighted sum
      Each input multiplied by its weight, then all added together.
      Deep Understanding
      • A weight is the importance the model gives to an input.
      • Large magnitude = strong influence; a weight near 0 = almost no influence.
      • The sign gives the direction: positive raises the output, negative lowers it.
      • Weights start random and are adjusted by gradient descent to reduce loss.
      • In deep networks, single weights mean little to humans; only their collective behaviour matters.
      Explanation
      In simple words

      A weight is a number saying how much a feature affects the output. A bigger weight means more effect; a negative weight pushes the output the other way.

      Example · Will a student pass the exam?
      • Feature 1: study hours → weight +0.8 (strong positive effect)
      • Feature 2: attendance % → weight +0.3 (mild positive effect)
      • Feature 3: daily phone hours → weight −0.5 (negative effect)
      • Feature 4: shoe size → weight ≈ 0 (no effect)

      The model learned these weights itself during training. Nobody told it that study matters most; the data did.

      How weights change during training

      Weights start out random. After each wrong prediction, the model works out which weights pushed the error up and nudges them a little (this is gradient descent). After thousands of rounds, the weights settle at good values.

      Try it · Spam prediction with weights and bias

      An email has a count of links and CAPITAL words. Change the weights and bias to see how the model's decision changes.

      Input features (email)
      4
      2
      Model parameters
      0.6
      0.4
      -3.0
      z = 0.6×4 + 0.4×2 + (−3.0) = 0.20
      Spam probability
      0.55 Spam

      Probability = sigmoid(z), which squeezes z into the 0–1 range. Above 0.5 means Spam (the threshold). Make the bias very negative: the same email becomes "Not Spam".

      Tester Focus

      If the model gives a large weight to a feature that should not matter (such as gender or pin code in loan approval), that is a fairness bug. Test it by changing only that one feature, keeping everything else the same, and checking whether the output changes.

      What does it mean if a feature's weight is close to 0?

      The model considers that feature to have almost no effect on the output. Removing it would barely change the prediction.

      Summary: Weight = how important an input is. Larger = more effect; negative = opposite effect.

      Bias

      What bias means in machine learning, and how biased data or assumptions distort model outputs.

      Technical Definition

      In machine learning, bias has two main meanings. (1) The bias term is a learnable parameter added to the weighted sum that offsets the output independently of the inputs. (2) Model / data bias is a systematic error that makes a model produce skewed or unfair outputs for certain groups, typically caused by unrepresentative data or flawed assumptions.

      (1) y = w·x + b (2) accuracy(group A) ≫ accuracy(group B)
      Terms Used
      Bias term (b)
      A constant number added to every prediction; also called the intercept.
      Weighted sum
      Inputs multiplied by their weights and added together.
      Offset
      Shift the whole output up or down by a fixed amount.
      Systematic error
      An error that repeats in the same direction, not a random one-off.
      Skewed output
      Results that lean unfairly towards or against some group.
      Unrepresentative data
      Data that doesn't reflect the real population, e.g. mostly one gender or region.
      Assumption
      Something the designers took as true without checking.
      Fairness
      The model treats similar people similarly, regardless of protected traits.
      Deep Understanding
      • The bias term is necessary and harmless; model bias is a defect.
      • A model learns whatever is in the data, including prejudice.
      • High overall accuracy can hide poor accuracy for one subgroup.
      • Deleting a sensitive column doesn't remove bias, because proxies (like pin code) carry the same signal.
      • Bias must be tested group by group (slice testing).
      Explanation

      "Bias" in ML has two different meanings. Know both, or it gets confusing.

      Meaning 1: bias as a parameter (the bias term)

      In simple words

      The bias term is an extra number added to every prediction whatever the input. It shifts the output's starting point (baseline).

      In Price = w × Area + b, if Area = 0, the price is still b, like a base land price. The bias slider in the demo above does exactly this: it slides the whole probability up or down. It is a normal, necessary part of a model, not a problem.

      Meaning 2: bias as unfairness (data / model bias)

      In simple words

      Model bias is when a model consistently treats some group wrongly or unfairly, because its training data or assumptions were one-sided. A model learns what is in its data, flaws included.

      Real examples
      • Hiring tool: trained on 10 years of resumes that came mostly from men, it learned to score women's resumes lower.
      • Face recognition: trained mostly on lighter-skinned faces, it makes more mistakes on darker skin.
      • Voice assistant: trained only on American accents, it struggles with Indian accents.

      Where bias comes from

      • Sampling bias: some groups weren't equally represented in the data.
      • Historical bias: past social discrimination was already in the data.
      • Labeling bias: the labellers' own views crept into the labels.
      • Assumption bias: the designers made a wrong assumption.

      Bonus: bias–variance in brief

      There's a third use in ML. High bias = the model is too simple to capture the pattern (underfitting). High variance = the model memorised the training data and fails on new data (overfitting). A good model balances the two.

      Tester Focus
      • Don't measure only overall accuracy; measure it separately for each group (gender, region, language, age). Overall can be 95% while one group gets 70%.
      • Counterfactual test: change only the name "Rahul" to "Priya", or the city "Delhi" to "Imphal". The output should not change where that detail shouldn't matter.
      • Deliberately include minority and edge groups in the test dataset.
      Are the "+ b" bias in a formula and a "biased model" the same thing?

      No. "+ b" is a normal parameter that shifts the output. A "biased model" means unfair, one-sided behaviour, which mostly comes from biased data.

      Summary: Bias term = a parameter that shifts the baseline. Model bias = unfair behaviour learned from biased data.

      Training vs Inference

      The difference between training a model and using a trained model to produce outputs.

      Technical Definition

      Training is the computational process of fitting a model's parameters to a dataset by repeatedly computing predictions, measuring loss, and updating parameters through optimisation, often over several epochs. Inference is the process of using the trained model, with its parameters frozen, to compute outputs for new, unseen inputs, typically after deployment and under latency constraints.

      Terms Used
      Fitting
      Adjusting parameters until the model matches the training data well.
      Loss
      A number measuring how wrong the model's predictions are.
      Optimisation
      Repeatedly changing parameters to make the loss smaller.
      Epoch
      One complete pass of the model through the entire training dataset.
      Frozen parameters
      Parameters that are locked and no longer change.
      Unseen input
      Data the model didn't see during training.
      Deployment
      Putting the trained model into a live app or server where real users use it.
      Latency
      How long the model takes to return an answer, e.g. 120 ms.
      Deep Understanding
      • Training changes the model; inference only uses it.
      • Training is costly and occasional; inference is cheap and happens constantly.
      • By default a model does not learn from users during inference.
      • Inputs at inference must be processed exactly as they were in training.
      • Inference quality can decay over time as the world changes (data drift).
      Explanation
      In simple words

      Training is the model studying (learning its parameters from data). Inference is the model sitting the exam (answering new inputs). During inference, the parameters do not change.

      PointTrainingInference
      PurposeBuild / teach the modelGet answers from the model
      DataLarge labeled datasetOne or a few new inputs
      ParametersChangeFixed
      Time / costHours to weeks; very expensiveMilliseconds to seconds; cheap
      How oftenOnce, or periodic retrainingOn every user request, millions of times
      WhereDevelopment / ML pipelineProduction (the live app)
      AnalogyLearning to driveDriving every day after learning
      Tester Focus
      • Testers mostly test inference: the model's output in the live app, response time (latency), and behaviour under load.
      • Training-serving mismatch: if production inputs are formatted differently from training data (say, training used lowercase text and the app sends uppercase), the model will give wrong outputs. Always test input preprocessing.
      • During inference the model does not learn from user input (unless it is explicitly retrained).
      A user gave feedback 100 times in the app. Will the model change right away?

      Usually not. Parameters stay fixed during inference. The feedback may be collected and used in the next training run, producing a new model version.

      Summary: Training = learning (parameters change); inference = using (parameters fixed).

      Prediction

      How a trained model produces a prediction from input data.

      Technical Definition

      A prediction is the output ŷ that a trained model computes for a given input by applying its learned function, typically a probability distribution over classes or a continuous estimate, which is then converted into a final decision, often by applying a threshold. It usually comes with a confidence score.

      ŷ = f(X_new; θ_trained) → P(Spam) = 0.92 → 0.92 ≥ 0.5 → "Spam"
      Terms Used
      ŷ (y-hat)
      The predicted output, as opposed to the true value y.
      Probability distribution
      A probability for each possible answer, all adding up to 1 (e.g. Cat 0.95, Dog 0.04, Rabbit 0.01).
      Class
      One of the possible categories the model can choose.
      Continuous estimate
      A numeric output that can take any value, such as ₹48.6 lakh.
      Threshold
      The cut-off value that turns a probability into a yes/no decision, often 0.5.
      Decision
      The final action or label the app uses, e.g. "move to spam folder".
      Confidence score
      How sure the model is about its answer, from 0 to 1.
      Deep Understanding
      • A prediction is an estimate, not a fact.
      • Confidence ≠ correctness: a model can be very confident and still wrong.
      • Choosing the threshold is a business decision that changes outcomes.
      • Predictions are reliable only for inputs similar to the training data.
      • The same model output can trigger different app actions depending on the threshold.
      Explanation
      In simple words

      A prediction is what the trained model says when it sees a new input. It is the model's best guess, not a guaranteed truth.

      How a prediction is formed, step by step

      1. Input arrives: e.g. one email.
      2. Preprocessing: the input is turned into numbers (features): links = 4, CAPS = 2…
      3. Calculation: features × weights + bias, through the model's layers.
      4. Raw score → probability: e.g. 0.92 (92% spam).
      5. Threshold / decision: 0.92 > 0.5, so the final label is "Spam".
      6. Output to the app: the email moves to the spam folder.

      Predictions come with confidence

      Most models return a confidence score along with the answer: "Cat: 0.95, Dog: 0.04, Rabbit: 0.01". High confidence does not mean the answer is definitely right. A model can be fully confident and still wrong.

      Why predictions go wrong

      • The input is very different from the training data (the model has never seen anything like it).
      • The training data was too small, wrong or biased.
      • The input itself is ambiguous (e.g. a mixed review).
      • The real world changed (e.g. shopping patterns after COVID). This is called data drift.
      Tester Focus
      • Test the threshold: the app's behaviour at 0.49 and 0.51 confidence (the AI version of boundary testing).
      • Give "out-of-distribution" inputs: empty input, very long text, emoji, another language, the wrong kind of image. The model shouldn't crash, and the app should handle low confidence gracefully.
      • Prediction quality can drop over time in production (data drift), so monitoring is essential.
      A model said "this is a cat" with 99% confidence, but the photo was a dog. Is that possible?

      Yes. Confidence is the model's own belief, not a guarantee of truth. That's why testing measures real accuracy, not just confidence.

      Summary: Prediction = input → features → weighted calculation → probability → threshold → final output.

      Classification vs Regression

      The difference between categorical prediction and numerical prediction problems.

      Technical Definition

      Classification is a supervised-learning task in which the model predicts a discrete class label from a finite set of categories (binary or multi-class). Regression is a supervised-learning task in which the model predicts a continuous numeric value. Each is evaluated with its own error metrics.

      Terms Used
      Supervised-learning task
      A problem solved by learning from labeled examples.
      Discrete
      Separate, countable options with nothing in between (Spam or Not Spam).
      Class label
      The name of the category, e.g. "Cat".
      Finite set
      A fixed, limited list of possible answers.
      Binary / Multi-class
      Two possible classes / more than two possible classes.
      Continuous
      Any value within a range, including decimals (₹48.73 lakh).
      Error metric
      A formula that measures how good or bad the predictions are (accuracy, MAE…).
      Deep Understanding
      • Ask: "Which one?" → classification; "How much?" → regression.
      • Classifiers usually output probabilities first, then apply a threshold to pick a class.
      • Regression error is a distance (how far off); classification error is right or wrong.
      • The same problem can be framed either way: an exact price (regression) or a price band (classification).
      • The wrong metric misleads: accuracy on imbalanced data can look great while the model is useless.
      Explanation
      In simple words

      Classification = the output is a category ("which one?"). Regression = the output is a number ("how much?"). Both are types of supervised learning.

      A quick trick to tell them apart

      Ask: "Is the answer chosen from a fixed list of options, or can it be any number?" Options → classification. Any number → regression.

      PointClassificationRegression
      OutputCategory (label)Number (value)
      QuestionWhich one? Yes or no?How much? How many?
      ExamplesSpam / not spam, cat / dog / bird, loan approve / reject, sentiment positive / negativeHouse price, tomorrow's temperature, delivery time, next month's sales
      TypesBinary (2 classes), multi-class (2+ classes)Linear, polynomial, etc.
      Measuring errorAccuracy, precision, recall, confusion matrixMAE, MSE, RMSE (how far off)
      What a mistake meansWrong category (right or wrong)Off by some amount (₹2 lakh off)

      Metrics in brief

      • Accuracy: how many were right out of all.
      • Precision: of those labelled "Spam", how many really were spam (few false alarms?).
      • Recall: of all real spam, how many were caught (anything missed?).
      • MAE (Mean Absolute Error): the average amount the predictions were off by, e.g. "₹3 lakh on average".
      Tester Focus
      • Classification tests: expected = the exact class. Build a confusion matrix to see which classes get mixed up. In medical or fraud cases, missing a positive (low recall) is the more dangerous error.
      • Regression tests: don't match exact numbers. Use a tolerance: "pass if the predicted price is within ±10% of actual." Add sanity checks too: no negative prices, and a bigger house shouldn't cost less than a smaller one.
      "Will the customer leave the app next month?" vs "How much will the customer spend next month?" Which is which?

      The first is classification (yes/no). The second is regression (an amount).

      Summary: Classification = "which one" (a category). Regression = "how much" (a number).

      Summary & Cheat Sheet

      AI is the field of making machines intelligent. Its most popular approach is machine learning, where a machine learns from a dataset. Each example in a dataset has features (inputs) and often a label (the right answer). Learning with labels is supervised, without labels is unsupervised, and from rewards is reinforcement learning. During training, the model adjusts its parameters (weights and bias). The trained model then makes a prediction on new input during inference, which can be a category (classification) or a number (regression). If the data is biased, the model will be biased too.       Practice Questions

      Think it through first, then click to see the full explanation.

      1. What is the biggest difference between testing traditional software and testing AI software?

      Traditional software is deterministic, so a test case compares the actual output with one exact expected value and the result is a clear pass or fail. AI software is probabilistic: the same input can give slightly different outputs, and even a well-working model is wrong on some inputs. So instead of one exact value, AI testing defines acceptable criteria (e.g. "label = Spam with confidence ≥ 0.8"), runs the same input several times to check consistency, and measures accuracy across a large test dataset. In short, traditional testing asks "is this one output correct?" while AI testing asks "how often, and how reliably, is the output acceptable?"

      2. "How many people are in this photo?" and "Is there a person in this photo?" What kind of problems are these?

      "Is there a person in this photo?" has only two possible answers, yes or no, so it is binary classification. "How many people?" has a numeric answer (0, 1, 2, 3 …), so it is closer to regression; in practice it is usually solved by object detection, where the model finds each person and counts them. The deciding question is always the type of output: a fixed list of categories means classification, a number means regression. A tester would check the first with exact match and a confusion matrix, and the second with the size of the error (e.g. off by one person).

      3. A model has 99% training accuracy but only 60% test accuracy. What happened?

      This is overfitting (high variance). The model memorised the training examples, including their noise and accidental details, instead of learning the general pattern, so it fails on data it hasn't seen. It's like a student who memorised last year's answer key and then faces new questions in the real exam. Common causes are too little training data, a model with too many parameters for that data, or training for too long. The large gap between training and test accuracy is the key warning sign a tester should report.

      4. In a loan model, changing only the applicant's gender (everything else the same) changed the decision. What does this indicate?

      It indicates model bias (unfairness). Since everything except gender stayed the same, gender alone changed the outcome, which means the model has learned to give weight to a feature that shouldn't affect a loan decision. This usually happens when historical data reflects past discrimination, for example fewer approved loans for women. The technique used here is a counterfactual fairness test, and the finding is a valid, high-severity bug that should be reported with the exact input pairs used.

      5. Explain the difference between weights and hyperparameters.

      Weights are parameters: numbers inside the model that it learns automatically from data during training, and they decide how much each input affects the output. Hyperparameters are settings a person chooses before training starts, such as the learning rate, number of layers or number of epochs; the model does not learn them. Think of weights as what a student learns, and hyperparameters as how the teacher chose to teach (how long, how fast). Changing hyperparameters changes how training happens, which in turn leads to different learned weights.

      6. A chatbot sometimes gives a correct fact and sometimes a wrong one for the same question. What should a tester do?

      Because the system is probabilistic, one correct run proves nothing, so the tester should run the same prompt many times (say 20) and record how often the fact is wrong. The bug report should include the exact prompt, the model version, settings such as temperature, sample correct and incorrect outputs, and the failure rate (e.g. "wrong in 6 of 20 runs"). It should be reported as inconsistent factual output, not dismissed as normal variation, because the variation is in meaning and not just wording. That failure rate also gives the team a baseline to check whether a fix actually works.

      7. Which type of learning best fits teaching a self-driving car to drive, and why?

      Reinforcement learning fits best, usually combined with supervised learning. Driving is a sequence of decisions where each action (brake, steer, accelerate) changes the next situation, which is exactly the agent–environment–reward loop of RL. The car (agent) earns rewards for safe, smooth progress and penalties for collisions or breaking rules, and learns a policy over many simulated trips. Supervised learning is still used for parts like recognising pedestrians and road signs from labeled images.

      8. A shop wants to find groups of similar customers, but has no predefined groups. Which learning type fits, and how would you test it?

      This is unsupervised learning, specifically clustering, because there are no labels saying which group each customer belongs to; the model forms groups from similarities in purchase data. Since there is no "right answer", a tester checks whether the groups make business sense (e.g. a clear "festival shopper" group), whether they are stable when the model is rerun on the same data, and whether each customer lands in only one sensible group. Humans then review and name the clusters before the business uses them.
